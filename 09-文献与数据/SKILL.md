# 09 文献与数据（Literature & Data）

## 一、模块定位

本模块负责建立科研活动的信息基础设施。

科研工作必须建立在可靠的文献证据和真实的数据基础上。

本模块不以收集论文数量和数据文件数量为目标，而是建立一套能够持续发现、筛选、分析、验证和管理科研信息的体系。

重点建设以下能力：

1. 学术资源检索
2. 文献筛选与评价
3. 文献精读与知识提取
4. 文献综述与研究现状分析
5. 系统综述与文献计量
6. 文献管理与知识组织
7. 科研数据获取
8. 数据清洗与质量控制
9. 数据分析与可视化
10. 数据引用与来源追溯
11. 数据共享与科研伦理
12. AI辅助文献与数据管理

核心原则：

- 优先使用可靠、可追溯的原始来源。
- 区分论文元数据、论文摘要和论文全文。
- 区分相关性、研究质量和证据强度。
- 不将搜索结果数量等同于研究成果质量。
- 不编造文献、DOI、作者、期刊和数据来源。
- 不将未经验证的数据用于重要研究结论。
- 保留原始数据和完整处理记录。

## 二、学术数据库与文献检索

### 2.1 学术数据库分类

建立多渠道文献检索能力。

#### 综合学术检索

- Google Scholar
- OpenAlex
- Semantic Scholar
- Crossref
- Dimensions
- Web of Science
- Scopus

#### 中文学术资源

- 中国知网（CNKI）
- 万方数据
- 维普
- 国家科技图书文献中心
- 国家哲学社会科学文献中心

#### 专业领域资源

- ASCE Library
- TRID
- ScienceDirect
- SpringerLink
- IEEE Xplore
- ASTM相关标准资源
- 各高校及科研机构知识库

#### 开放获取资源

- DOAJ
- CORE
- OpenAIRE
- arXiv
- Zenodo
- Figshare
- Dryad

注意：

不同数据库的收录范围、检索能力、访问权限和元数据质量不同。

不能将某一个数据库视为全部学术成果的完整集合。

### 2.2 检索策略

采用由宽到窄的检索方法。

第一步：确定研究主题。

第二步：拆解核心概念。

第三步：建立中英文关键词。

第四步：寻找同义词、缩写和专业术语。

第五步：使用布尔逻辑组合检索。

第六步：限定时间、领域、文献类型等条件。

第七步：检查检索结果并调整策略。

常用检索逻辑：

- AND：同时包含多个条件。
- OR：包含任意一个同义词。
- NOT：排除不需要的主题。
- ""：精确短语检索。
- *：部分数据库支持截词检索。

### 2.3 专业领域检索示例

以桥梁吊索风致振动为例：

英文核心词：

- Bridge cable
- Stay cable
- Suspension cable
- Wind-induced vibration
- Rain-wind-induced vibration
- Vortex-induced vibration
- Structural health monitoring
- Vibration prediction
- Machine learning

组合检索示例：

("stay cable" OR "bridge cable")
AND
("wind-induced vibration" OR "rain-wind-induced vibration")
AND
("prediction" OR "monitoring" OR "machine learning")

中文检索词：

- 桥梁吊索
- 斜拉索
- 风致振动
- 雨风致振动
- 涡激振动
- 结构健康监测
- 振动预测
- 智能识别

检索词应根据具体研究问题不断迭代。

### 2.4 检索策略记录

每次重要检索应记录：

- 研究主题
- 数据库名称
- 检索日期
- 检索式
- 时间范围
- 文献类型
- 语言限制
- 检索结果数量
- 筛选规则
- 检索人员
- 检索版本

确保未来能够复现检索过程。

## 三、文献筛选与质量评价

### 3.1 初步筛选

根据以下信息判断文献是否值得进一步阅读：

- 标题
- 摘要
- 关键词
- 研究对象
- 研究方法
- 主要结论
- 发表时间
- 文献类型

### 3.2 纳入与排除标准

在正式检索前，尽可能明确：

纳入标准：

- 与研究问题直接相关。
- 研究对象和研究场景符合要求。
- 具有可识别的研究方法。
- 能够获取足够的研究信息。
- 符合预先确定的时间及语言条件。

排除标准：

- 明显偏离研究主题。
- 重复记录。
- 缺少关键研究信息。
- 无法确认来源真实性。
- 不符合预先确定的纳入条件。

排除文献时应记录原因，避免选择性筛选。

### 3.3 文献质量评价

重点检查：

1. 研究问题是否明确？
2. 理论依据是否充分？
3. 研究设计是否合理？
4. 样本是否具有代表性？
5. 数据是否可靠？
6. 方法是否适用？
7. 结果是否有足够证据支持？
8. 是否讨论研究局限？
9. 是否存在利益冲突？
10. 是否存在撤稿、勘误或重大更新？

不能仅凭期刊影响因子、引用次数或作者知名度判断一篇论文的研究质量。

## 四、文献精读与信息提取

### 4.1 文献阅读层次

采用三层阅读法。

第一层：快速浏览

- 标题
- 摘要
- 关键词
- 引言
- 结论
- 图表

目的：判断研究价值。

第二层：结构化阅读

- 研究背景
- 科学问题
- 理论基础
- 研究方法
- 实验设计
- 数据来源
- 主要结果
- 创新点
- 不足之处

目的：理解论文整体逻辑。

第三层：深度精读

- 公式推导
- 实验条件
- 模型假设
- 参数设置
- 统计方法
- 图表细节
- 结果解释
- 参考文献
- 可复现性

目的：掌握能够借鉴的方法和技术。

### 4.2 文献阅读卡片

每篇重要文献建立一张阅读卡片：

- 文献编号：
- 论文标题：
- 作者：
- 发表年份：
- 期刊或会议：
- DOI：
- 原始链接：
- 研究领域：
- 研究对象：
- 核心问题：
- 研究目的：
- 理论依据：
- 研究方法：
- 数据来源：
- 主要结果：
- 主要创新：
- 研究局限：
- 可借鉴内容：
- 与当前项目的关联：
- 个人评价：
- 阅读日期：
- 阅读状态：

阅读卡片应区分作者原文结论与自己的分析判断。

### 4.3 文献对比矩阵

对同一研究主题的多篇论文建立对比表。

| 对比维度 | 文献A | 文献B | 文献C |
|---|---|---|---|
| 研究对象 | | | |
| 研究问题 | | | |
| 理论基础 | | | |
| 研究方法 | | | |
| 数据来源 | | | |
| 主要结果 | | | |

- 已有研究的共识
- 不同研究的分歧

- 值得继续研究的方向

## 五、文献综述与研究现状分析

### 5.1 文献综述基本结构

1. 研究背景
2. 研究主题的发展过程
3. 国内外研究现状
4. 主要研究方法
5. 代表性研究成果
6. 不同研究观点比较
7. 当前存在的问题
8. 未来发展方向
9. 本研究的切入点

### 5.2 综述写作原则

- 不以作者名单代替研究分析。
- 不以论文摘要简单拼接全文。
- 不将不同研究的结论强行合并。
- 不忽视相互矛盾的研究证据。
- 重要结论应找到原始文献支持。
- 对引用内容准确标注出处。
- 区分已有成果与自己的判断。

### 5.3 研究空白识别

重点寻找：

- 尚未充分研究的对象
- 尚未解决的理论问题
- 现有方法的局限
- 数据规模或质量不足
- 特定环境下的适用性问题
- 不同学科之间的研究断层
- 工程实际与理论研究之间的差距

研究空白不能仅凭“研究较少”来判断，必须通过系统检索和证据比较加以支持。

## 六、系统综述与文献计量

### 6.1 系统综述

系统综述应具有明确、可复现的方法。

主要流程：

研究问题确定
→ 制定研究方案
→ 确定数据库
→ 设计检索式
→ 检索文献
→ 去重
→ 标题与摘要筛选
→ 全文筛选
→ 质量评价
→ 数据提取
→ 综合分析
→ 报告结果

### 6.2 PRISMA流程

在适用的系统综述中，可参考PRISMA 2020报告规范。

重点记录：

- 检索发现的记录数量
- 去重后的记录数量
- 初步筛选数量
- 全文评估数量
- 排除数量及原因
- 最终纳入研究数量

PRISMA是报告规范，不是自动保证研究质量的工具。

### 6.3 文献计量分析

重点掌握：

- 发文量变化
- 作者合作网络
- 机构合作网络
- 国家与地区分布
- 关键词共现
- 共被引分析
- 文献耦合
- 研究主题演化
- 学科交叉分析

常用工具：

- VOSviewer
- CiteSpace
- Bibliometrix
- R
- Python

文献计量结果需要结合研究主题解释，不能简单把网络图等同于学术价值。

## 七、文献管理与知识组织

### 7.1 文献管理工具

重点了解：

- Zotero
- EndNote
- Mendeley
- JabRef

工具选择应考虑：

- 文献数量
- 团队协作
- 引用格式
- PDF管理
- 标签和笔记
- 数据同步
- 隐私与存储成本

### 7.2 文献分类体系

建议按照研究项目和专业领域建立分类。

示例：

文献库/
├── 道路工程/
├── 桥梁工程/
├── 隧道工程/
├── 岩土工程/
├── 工程材料/
├── 工程结构/
├── 智能建造/
├── 人工智能/
├── 科研方法/
└── 跨学科研究/

同一篇文献可以通过标签关联多个主题，不必重复保存多个副本。

### 7.3 标签体系

推荐标签：

- 理论基础
- 研究方法
- 实验设计
- 数值模拟
- 数据集
- 关键结论
- 创新点
- 研究不足
- 重要参考
- 待精读
- 已精读
- 项目相关

### 7.4 文件命名

建议采用：

年份_第一作者_关键词_文献类型

例如：

2025_Zhang_BridgeCableVibration_Article.pdf

不得只依赖文件名管理文献，应同时保留完整元数据和唯一标识符。

## 九、数据质量控制

### 9.1 数据质量维度

重点评价：

- 准确性
- 完整性
- 一致性
- 时效性
- 代表性
- 可追溯性
- 可复现性

### 9.2 数据检查流程

原始数据接收
→ 来源核查
→ 格式检查
→ 完整性检查
→ 单位检查
→ 异常值检查
→ 重复值检查
→ 逻辑检查
→ 清洗与转换
→ 质量记录
→ 数据归档

### 9.3 数据清洗原则

- 原始数据必须保留。
- 清洗操作应有记录。
- 不得无理由删除异常值。
- 不得人为修改数据以迎合假设。
- 对缺失值处理方法作出说明。
- 对单位转换进行记录。
- 保留清洗前后的数据对照。
- 对无法确认的数据标记为待核实。

### 9.4 数据异常分析

常用方法：

- 箱线图
- Z-score
- IQR
- 时间序列检查
- 逻辑约束检查
- 传感器状态检查
- 多变量异常检测

异常值不一定是错误数据，必须结合工程背景判断。

## 十一、数据可视化与表达

推荐建立统一绘图规范。

常用图表：

- 折线图
- 散点图
- 柱状图
- 直方图
- 箱线图
- 热力图
- 相关性矩阵
- 时序图
- 等高线图
- 空间分布图

图表必须明确：

- 数据来源
- 变量定义
- 坐标轴名称
- 单位
- 样本数量
- 统计方法
- 误差表达
- 图例含义

避免使用不合理的坐标范围、误导性比例和缺乏依据的趋势线。

## 十二、数据引用与来源追溯

### 12.1 文献引用

引用文献时应核对：

- 作者
- 标题
- 期刊或会议
- 发表年份
- 卷期
- 页码或文章编号
- DOI
- 原始出版页面

引用前应尽可能检查原始文献，而不是只依据其他论文的转述。

### 12.2 数据引用

数据集应尽可能记录：

- 数据集名称
- 作者或创建机构
- 发布年份
- 版本
- DOI或永久标识符
- 数据仓储
- 许可协议
- 获取日期
- 数据处理说明

数据集引用不能只写一个网页链接。

### 12.3 引用关系

建立：

研究结论
→ 原始文献
→ 数据来源
→ 数据版本
→ 分析方法
→ 处理代码
→ 最终图表

确保研究结论可以追溯到实际证据。

## 十三、科研数据管理与复现

### 13.1 数据管理目录

建议采用：

项目名称/
├── README.md
├── metadata/
├── raw_data/
├── processed_data/
├── analysis/
├── figures/
├── scripts/
├── results/
├── references/
└── documentation/

### 13.2 数据分层

RAW：原始数据，不直接覆盖。

PROCESSED：经过清洗和转换的数据。

ANALYSIS：用于统计分析和建模的数据。

RESULTS：最终结果、图表和报告。

### 13.3 版本管理

重要数据应记录：

- 数据版本
- 修改时间
- 修改人员
- 修改内容
- 处理程序版本
- 参数设置
- 文件校验信息

大型数据集不应不加区分地直接上传GitHub。

应根据文件大小、授权情况和隐私要求选择合适的数据仓储或版本管理方式。

### 13.4 可复现性

重要分析项目应保存：

- 原始数据或合法获取方式
- 数据字典
- 处理代码
- 软件环境
- 依赖版本
- 参数配置
- 随机种子
- 分析过程
- 最终结果

确保其他研究者能够理解并在条件允许时复现研究过程。

### 14.2 数据辅助

AI可以协助：

- 编写数据处理程序
- 生成数据清洗脚本
- 解释统计方法
- 生成可视化代码
- 检查数据结构
- 编写数据字典
- 辅助异常值分析

### 14.3 AI使用限制

- 不得将AI生成的文献当作真实文献。
- 必须核对论文标题、作者、DOI和出版信息。
- 不得将AI总结替代原文证据。
- 不得将AI推测的数据当作实验数据。
- 不得未经许可上传受限制的科研资料。
- 不得将AI生成的统计结论直接作为最终结论。
- 对重要研究结果必须进行独立核验。

推荐流程：

AI辅助检索
→ 数据库核实
→ 获取原始文献
→ 阅读与提取
→ 建立文献卡片
→ 人工检查
→ 纳入知识库

每项外部资源应标记：

- DISCOVERED：已发现。
- REVIEWED：已阅读。
- VERIFIED：已核实。
- ADAPTED：已转化为可复用方法或工具。
- DEPRECATED：已过时或不再推荐。

资源记录至少包括：

- 资源名称
- 资源类型
- 作者或机构
- 官方链接
- 版本或发布日期
- 适用领域
- 访问权限
- 许可协议
- 核验状态
- 最后核验日期
- 使用评价

不得把仅仅搜索到的资源标记为已验证。

## 十六、模块建设目标

本模块最终形成六项核心能力：

1. 文献发现能力：能够系统寻找高质量研究资料。
2. 文献评价能力：能够判断研究质量和证据价值。
3. 文献综合能力：能够发现研究进展、分歧与空白。
4. 数据获取能力：能够寻找可靠且合法的数据来源。
5. 数据分析能力：能够完成数据整理、质量控制和统计分析。
6. 证据追溯能力：能够将研究结论追溯到原始文献和数据。

最终目标：

建立一个可靠、可追溯、可复现、持续更新的科研文献与数据基础设施，为整个Research-Intelligence-Hub提供信息与证据支持。
