# 科研成果知识产权保护工作流（RIH）

## 目标

在项目研发、论文投稿、竞赛展示、代码公开或成果转化前，识别潜在知识产权成果，控制过早公开和权属不清风险，并选择适当的保护与登记路径。

本工作流是团队内部管理建议，不替代学校制度、法律意见或专利代理师的专业判断。

## 一、成果发现

项目启动及每个阶段评审时，建立成果台账，记录：

- 技术方案、结构设计、算法实现、软件程序、数据库、图纸、文档和实验装置；
- 首次形成日期、版本号、实际贡献人员和证据位置；
- 计划投稿、参赛、演示、开源或对外交流的时间；
- 项目资助、任务书、合作开发和委托开发关系。

不要等到论文或竞赛截止前才第一次讨论成果归属。

## 二、公开前控制

在以下活动之前进行一次公开前审查：

- 论文投稿、预印本发布和学术会议报告；
- 竞赛材料提交、公开路演和展览；
- GitHub 公开仓库、网站、视频或社交媒体发布；
- 向企业、合作单位或外部评审展示技术细节。

逐项确认：拟公开内容是否包含可能申请专利的技术特征、未公开源代码、保密数据、第三方资料或个人信息。必要时先暂停公开，向学校知识产权管理部门或专利代理师咨询。不要自行假设“竞赛展示不算公开”或“网上只有少量内容就没有影响”。

## 三、权属与贡献核查

1. 区分实际开发者、发明人、作者、申请人和著作权人。
2. 查看项目任务书、合作开发协议、委托开发合同、学校制度和资助协议。
3. 记录每个人对技术实质特征、代码模块、文档和实验的真实贡献。
4. 检查是否使用第三方代码、开源组件、数据、图纸或素材。
5. 对权属不明、共同开发未约定或涉及学校职务成果的情况，先取得书面意见。

## 四、选择保护路径

| 成果形态 | 可评估的保护路径 | 关键判断 |
|---|---|---|
| 新的产品结构或技术方法 | 发明/实用新型专利（按法定客体评估） | 是否存在可实施的技术方案、区别特征及相应证据 |
| 软件程序及相关文档 | 软件著作权登记；必要时另行评估发明专利 | 代码和文档的真实开发、表达及权属；算法思想本身不因软著登记受保护 |
| 不宜公开且具有商业价值的技术信息 | 商业秘密保护 | 是否采取合理保密措施、是否有必要公开申请 |
| 论文、图表、报告、数据库等作品 | 著作权及合同/许可管理 | 作品表达、作者与权利归属、第三方素材许可 |

不同保护路径可以组合，但保护对象和法律效果不同，不能互相替代。

## 五、专利路径

1. 使用国家知识产权局专利检索及分析系统检索相关现有技术。
2. 保存检索日期、检索式、分类号、相关专利和排除理由。
3. 用专利技术交底模板描述技术问题、方案、区别特征、实施例和技术效果证据。
4. 核实发明人及申请人，不将团队名称或AI系统列为发明人。
5. 由专利代理师或专业人员判断申请类型、权利要求和说明书。
6. 如考虑优先审查，对照现行《专利优先审查管理办法》核对适用条件、推荐意见和材料，不把优先审查当作普通加急服务。
7. 申请后保存受理通知、申请文件版本、答复期限和法律状态证据。

## 六、软件著作权路径

1. 确认软件真实完成、功能可说明、版本可复现。
2. 固定拟申请版本，记录源代码版本号、构建信息和开发时间线。
3. 核对开发者、著作权人、合作/委托/职务开发关系。
4. 形成第三方依赖与开源许可证清单。
5. 按软件著作权材料准备清单整理申请表、程序/文档鉴别材料及证明文件。
6. 通过中国版权保护中心当前登记网站核对格式和提交要求。
7. 保存提交文件、申请编号、补正通知和登记结果。

## 七、知识库回流

公开仓库只保存可公开、已脱敏且有权保存的内容，例如：

- 官方法规链接及自撰摘要；
- 空白工作模板和一般化检查清单；
- 不含敏感技术细节的流程经验；
- 已公开的登记信息和公开成果链接；
- 经权利人批准公开的代码或文档。

未公开的技术交底、完整源代码、身份证明、合同、签名、申请账户信息和敏感实验数据，应保存在团队受控私有空间。任何公开前都要再次确认权属和保密要求。

## 八、阶段验收

一次成果保护工作至少应留下：

- 成果台账及版本记录；
- 公开时间线和公开前审查结论；
- 贡献人、申请人/著作权人及权属依据；
- 专利检索日志（适用时）；
- 保护路径选择及理由；
- 申请材料清单和复核记录；
- 提交/受理/登记等真实凭证（如已办理）；
- 可公开的经验总结及其审核记录。

不得把“准备申请”“已经提交”“已经受理”“已经授权/登记”混为同一状态。

## 维护说明

本工作流为 RIH 原创初版，尚未用团队真实专利或软著申请完成端到端验证。使用真实案例后，应记录适用场景、遇到的问题、审核意见和修订内容，再考虑提升成熟度状态。
