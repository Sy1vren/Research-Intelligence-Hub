# 11 PDF 手写化

## 1. 模块目标

建立可在 Windows 本地运行、由手机浏览器安全调用的 PDF 手写排版系统，支持两种模式：

- **通用手写模式**：使用已获许可的中文手写字体，并加入轻微、可控的字距、位置、角度和墨色变化。
- **个人笔迹模式**：只使用用户本人主动提供的手写样本，建立逐字字形库；同一汉字可存放多个真实字形版本，渲染时轮换使用。

系统最终应支持：读取原 PDF → 指定填写区域 → 生成手写图层 → 叠加到原 PDF → 导出新 PDF。原始 PDF 永远只读，输出到新文件。

## 2. 重要技术边界

1. “手写字体”“真实字形拼接”和“AI 风格迁移”是不同技术，不得混为一谈。
2. 通用模式只是手写视觉模拟，不应声称是用户本人真实笔迹。
3. 个人模式优先使用用户真实书写的字形图像及其多个版本；未收录字符必须明确提示或按用户设置回退到通用字体，不能悄悄伪装成真实字形。
4. 少量样本不能自动保证生成所有汉字都像本人。若未来接入少样本风格迁移模型，必须单独验证模型来源、权重许可、显存/内存要求和真实效果。
5. 文字区域定位、OCR、表格理解和公式识别可能出错。未经用户确认，不得自动覆盖原有数据、公式、图表、签名或教师批注。
6. 不用于伪造他人笔迹、签名、授权、考勤、票据、证件或其他身份/法律凭证。只处理用户有权编辑且用途正当的文件。

## 3. 工作模式

### A. 通用手写

- 选择本地已安装或用户授权的 TTF/OTF 字体。
- 按字符渲染，不使用整段文本一次性排成机械字体。
- 对字形做轻微随机变化：旋转、水平/垂直偏移、字号、字距和墨色。
- 随机变化必须有上限；不可影响可读性、公式正确性或文字框边界。
- 使用固定 seed 时应可复现同一结果。
- 字体文件及其许可证必须单独核验；不能因为代码开源就假定字体也可再分发。

### B. 个人笔迹

- 先生成字符采集表，用户用平时的笔在纸上逐格书写。
- 拍摄/扫描时要求页面平整、四角完整、光线均匀、对焦清楚。
- 对字符切分结果进行人工校验，建立按 Unicode 字符命名的本地字形目录。
- 同一字符允许保存多个版本，渲染时随机选择，降低重复字形的机械感。
- 个人字形图像、训练样本和个人字体只保存在用户本机，不提交到公开 GitHub。
- 缺字处理策略必须由用户选择：停止并报告缺字，或使用通用字体回退并在预览中标记。
- 不将个人字形图像误称为完整的“AI 个人字体模型”。只有完成独立训练和验证后，才可称为风格迁移模型。

## 4. PDF 填写流程

1. **检查文件**：读取页数、页面尺寸、旋转方向、可提取文本和扫描页情况。
2. **确定填写内容**：由用户提供文字；不编造实验数据、测量值、计算结果或签名。
3. **定位区域**：先由用户在页面预览中指定矩形区域；OCR 仅作为辅助建议。
4. **生成预览**：逐页渲染透明笔迹层，检查文字是否越界、遮挡原内容或压线。
5. **用户确认**：确认每个填写框、字体模式、字号和排版。
6. **导出**：将透明图层叠加到原 PDF 的副本，输出到独立目录。
7. **验收**：重新打开输出 PDF，检查页数、页面尺寸、原始图表/公式是否保留、笔迹是否完整。
8. **保留原件**：不得覆盖上传的原始 PDF。

## 5. 当前 MVP 接口

当前版本提供 JSON 配置驱动的本地 CLI，支持：
- 以 PDF 页面坐标（point）指定文字框；
- 通用字体逐字渲染；
- 个人字形 PNG 目录渲染；
- 轻微字符级随机扰动；
- 透明图层叠加到 PDF 副本；
- 固定随机种子；
- 缺字报告与可配置回退。

示例配置见 `config/example.json`，运行说明见 `README.md`。

当前 MVP **不自动识别 PDF 中所有空白栏位**，也不承诺自动识别复杂公式/表格。区域需人工指定；浏览器可视化定位和手机端调用列入后续阶段。

## 6. 目录与数据安全

- 代码、文档、示例配置可以放在 GitHub。
- `private_data/`、`input/`、`output/`、个人字形、真实报告、训练照片必须留在本机。
- 不提交真实姓名、学号、签名、课程报告、个人字迹照片或任何 API 密钥。
- 公开仓库中只放合成测试样例或明确授权的示例。
- 建议定期备份个人字形库到用户自己的加密存储。

## 7. 质量验收标准

- [ ] 原始 PDF 不被覆盖。
- [ ] 输出 PDF 页数和页面尺寸与原件一致。
- [ ] 原 PDF 的图表、数据、公式和底图保持不变（仅增加指定文字图层）。
- [ ] 每个文字框均经用户确认。
- [ ] 文字不越界、不遮挡非填写区域。
- [ ] 中文字符无缺字、乱码或字体回退异常。
- [ ] 个人模式能报告字形库覆盖率和缺失字符。
- [ ] 固定 seed 可复现。
- [ ] 输出 PDF 可正常打开、打印。
- [ ] 真实个人样本没有上传到公共仓库或第三方服务。

## 10. GPT 调用规则

当用户要求“把文字手写到 PDF”“按我的笔迹填写 PDF”“生成手写报告”时：

1. 先确认是否有原始 PDF 和明确的填写文字。
2. 读取 PDF，区分已有内容与空白填写区。
3. 默认不修改原始数据、公式、图表、签名和批注。
4. 若用户选择个人模式，先检查本地字形库覆盖率；没有字库时指导采集，不得假称已学习用户笔迹。
5. 先生成预览供用户确认，再导出 PDF。
6. 输出后报告实际完成的页数、填写框数量、缺字和未处理区域。
7. 若当前环境无法访问用户本机服务或本地字形库，明确说明限制，不得声称已调用本地模型。

**最终原则：原件安全、内容准确、笔迹自然、过程可复现、个人数据留在本地。**
